# Flying Dragon

Я написал эту игру для сына, которому тогда было 5 лет. Мы сидели дома во время
самоизоляции от коронавируса, и мне хотелось развлечь себя и скучающего ребёнка.

Игра максимально простая - дракон должен собрать 10 кристаллов и не погибнуть.
Он может летать и стрелять огнём по врагам. Управление — стрелками и пробелом.
Враги не двигаются и умирают от попадания — но бьют, если к ним приблизиться.
После победы или поражения — новую игру можно начать обновлением страницы.

На устройствах с основным сенсорным управлением (`pointer: coarse`) появляются
экранные стрелки и кнопка «Огонь». Удерживание стрелки повторяет движение;
клавиатура продолжает работать.

Изменение размера окна сохраняет текущую игру, переносит объекты пропорционально
и удерживает их внутри поля. В очень маленьком окне спрайты уменьшаются.

## Разработка

Нужны Node.js 24 и npm. Если установлен nvm:

```sh
nvm use
npm ci
npm run dev
```

Открыть адрес, который выведет Vite. `npm run start:dev` — совместимый псевдоним.
Игровая логика находится в `src/index.js`, сенсорное управление —
в `src/touch-controls.js`, стили — в `src/style.css`,
HTML — в корневом `index.html`, изображения — в `src/img/`.

## Проверки

Для тестов деплоя (`npm run test:deploy`) нужен Python 3.

Перед первым запуском браузерных тестов:

```sh
npx playwright install chromium
```

На Linux может понадобиться `npx playwright install --with-deps chromium`.
Затем:

```sh
npm run check
npm test
npm run test:deploy
npm audit
```

`npm test` сам собирает production-версию, запускает её из подпапки
`/games/flying-dragon/` и проверяет в Chromium загрузку ресурсов, движение,
стрельбу, сбор кристаллов, урон, изменение размера окна, сенсорное управление,
подсказки и положение кнопок после победы и смерти. Для воспроизводимости поле
в тестах получает фиксированную последовательность случайных чисел. Тесты
столкновений размещают объекты в контролируемых позициях, затем используют
обычные клавиши.

GitHub Actions запускает установку, синтаксическую проверку, сборку,
браузерные тесты, тесты деплоя и аудит. При провале браузерных тестов
сохраняются трассы в артефактах.
Safari и Firefox этим набором не проверяются.

Push в `master` после успешных проверок автоматически публикует проверенную
сборку из `dist/`. Pull request выполняет только проверки. Тот же workflow
можно запустить вручную через GitHub Actions.

Деплой использует окружение `production`: секреты `HOSTER_HOST`, `HOSTER_USER`,
`HOSTER_SSH_KEY`, `HOSTER_KNOWN_HOSTS` и переменную `DEPLOY_URL`.
Отдельный SSH-ключ запускает только установленный на хостинге
`scripts/hoster_receiver.py`: он принимает статические файлы в каталог игры
и команду отката. После загрузки проверяются SHA-256 всех файлов по HTTPS;
при ошибке скрипт пытается восстановить предыдущую версию. Если подтвердить
откат не удалось, он сообщает об этом в логе GitHub Actions. Один снимок для
отката хранится вне web-каталога. Старые ресурсы сохраняются для уже открытых
страниц.
Изменение правил разрешённых файлов требует обновления установленного receiver.

## Сборка

```sh
npm run build
npm run preview
```

Vite создаёт статические файлы в `dist/`: HTML, CSS, JavaScript и изображения.
Ссылки на ресурсы относительные, поэтому сборку можно разместить в корне домена
или в подпапке.
